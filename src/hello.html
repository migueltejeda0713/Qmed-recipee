Introducción

Bienvenido a la documentación completa de la App de Tareas por Categoría en Angular. Aquí aprenderás a usar todas las características de Angular de forma práctica y profesional.

Este documento es autocontenible: incluye todo el HTML y CSS necesario.

Objetivo

Crear una aplicación que permita gestionar tareas clasificadas por categorías, aplicando:

  • Signals para estado reactivo.
  • Rutas hijas para navegación anidada.
  • Inyección de dependencias con servicios.
  • Principio de responsabilidad única (SOLID).
  • Inputs y Outputs para comunicación entre componentes.
  • Persistencia con LocalStorage.

Instalación

  1. Instala Angular CLI: npm install -g @angular/cli
  2. Genera el proyecto: ng new tarea-app --routing --standalone --style=scss
  3. Accede al proyecto: cd tarea-app
  4. Instala dependencias: npm install
  5. Inicia el servidor: ng serve --open

Signals

Señales reactivas para manejo de estado sin RxJS:

import { signal } from '@angular/core';
const tareas = signal<Tarea[]>([]);

StorageService

Servicio que usa signals y LocalStorage:

@Injectable({ providedIn: 'root' })
export class StorageService {
  private tareasSignal = signal<Tarea[]>(this.getFromStorage());

  private getFromStorage(): Tarea[] {
    return JSON.parse(localStorage.getItem('tareas') || '[]');
  }

  addTarea(t: Tarea) {
    const updated = [...this.tareasSignal(), t];
    this.tareasSignal.set(updated);
    localStorage.setItem('tareas', JSON.stringify(updated));
  }
}

TareasComponent

Filtra y muestra tareas de la categoría actual:

@Component({ /* ... */ })
export class TareasComponent {
  categoriaId = inject(ActivatedRoute).snapshot.paramMap.get('id')!;
  storage = inject(StorageService);

  tareasFiltradas() {
    return this.storage.tareas().filter(t => t.categoriaId === this.categoriaId);
  }
}

Principios SOLID

  • S: Una sola responsabilidad por clase/componente.
  • O: Extensible sin modificar base.
  • L: Sustitución de Liskov.
  • I: Interfaces específicas.
  • D: Inversión de dependencias.
